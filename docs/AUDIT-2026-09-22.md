# Stability and performance audit — 8.5.1 candidate

Status: tested engineering candidate; **not yet approved for Google Play**. Original v8.5 release remains available unchanged.

## Changes

| Area | Finding | Change |
|---|---|---|
| Large images | The old sample-size loop only reduced images when BOTH dimensions exceeded the viewport; a long panorama could decode at full size. | Bound both axes independently using overflow-safe arithmetic; 3072 px maximum axis, 1920 on low-RAM / <=128 MB heap devices. Shared sizing also protects gallery thumbnails. |
| Filter scheduling | Rapid adjustments cancelled coroutine jobs but CPU loops kept running; several effects could allocate large scratch buffers simultaneously. | One shared CPU lane for filters; cooperative cancellation in expensive pixel/row loops, blur and smoothing; cancellation is rethrown. |
| Outline strength | Changing opacity/strength rebuilt the same outline pixels. | Use an enabled/disabled key for strength; actual strength remains a paint operation. |
| Switching images | A previous source's filtered bitmap could remain visible while the new pipeline loaded. | Key the image composition by URI and viewport; clear pending overlay/thumbnail state. |
| Disabling effects | A stale cached base effect could win the render priority before its producer cleared. | Select base effect according to current enable flags. |
| Startup | A fixed three-second custom splash blocked input. | Reduce this delay to 350 ms; image decode remains asynchronous. This removes 2.65 seconds of intentional waiting, not a measured end-to-end startup benchmark. |
| Last image | A URI was written to preferences but never restored at startup. | Restore it, handle unavailable sources, and save only references with restorable access. Include persisted document-tree grants. |
| Preferences | Every repeated remote adjustment wrote the full settings set. | Coalesce writes over 250 ms; flush latest state on lifecycle stop/disposal. Abrupt process/device failure within that interval can lose the last adjustment. |
| Back | Main projection could toggle controls indefinitely. | Back closes transient panels / direct control / menus and then finishes the activity. Menu key remains a shortcut. |
| Display sleep | MainActivity re-added KEEP_SCREEN_ON on resume/focus regardless of the setting. | Only the user's setting owns this flag. Default remains Off. |
| EXIF | Legacy decoder did not orient photos on API 23; mirrored transpose/transverse were reversed. | AndroidX ExifInterface 1.4.2, corrected transforms and orientation dimensions. |
| Older Android | Overlay blend modes silently did nothing before API 29. | PorterDuff fallback for Multiply, Screen and Overlay. |
| Extreme adjustments | Movement/rotation could exceed what preference restore accepted. | Bound movement to saved limits and normalize rotations. |
| USB scanning | Directory traversal only bounded depth and image count; empty/looping directory trees could consume excessive work. | Cancellation checkpoints, visited-directory tracking and a 10,000-directory cap. Individual provider query latency is still controlled by the provider. |
| Release packaging | Release code/resource shrinking disabled. | Enable R8 and resource shrinking; build unsigned AAB and optimized APK. |
| Release hygiene | No automated regression suite, privacy screen or release checklist. | Add unit/device tests, GitHub build checks, in-app/public privacy policy and explicit Play gates. Version text derives from BuildConfig. |

## Executed validation

- Local Gradle: `testDebugUnitTest lintDebug assembleDebug assembleRelease bundleRelease assembleDebugAndroidTest` — successful.
- 7 JVM tests: sample sizing, panoramas, tall scans, small/odd dimensions, invalid input, range invariants.
- 6 instrumentation tests on an Android 16 TV emulator: nine filters at 1x1, 2x2 and 64x64; palette; input ownership; 12000x100 PNG; corrupt JPEG; pixel-by-pixel EXIF 5/6/7/8; repeated directional edits and save/restore across all tool modes; lock behavior.
- Device checks: saved image restore, Back exits to launcher, Keep Screen Awake off, Home/resume, concurrent active filters/palette. Screenshots inspected; no FATAL EXCEPTION in the captured log.
- Optimized release APK was signed with a LOCAL DEBUG KEY solely for installation in the temporary emulator. Release-code startup/rendering and Back exit passed. This is not a production signature.
- Android Lint: **0 errors, 58 warnings, 6 hints**. Remaining warnings include dependency updates, convenience APIs, unused/duplicate resources and icon styling; none were hidden by a baseline. OldTargetApi is evaluated against the TV-specific requirement in the Play checklist.
- Four native ABIs present (armeabi-v7a, arm64-v8a, x86, x86_64). All LOAD segments of `libandroidx.graphics.path.so` have 16384-byte alignment. `zipalign -c -P 16 4` passed on the test-signed release APK. A 16 KB runtime test remains outstanding.

## Artifact sizes and memory observations

- Preserved original v8.5 debug APK: 24,426,204 bytes.
- New unsigned optimized APK: 7,550,901 bytes; test signature adds a small amount.
- New unsigned AAB: 8,955,427 bytes.
- New debug APK: 26,932,869 bytes (includes debug tooling).

Do not present APK shrinkage as an apples-to-apples runtime speed improvement: the old artifact is a debug build, the small new one is optimized release code. A single combined-filter emulator snapshot showed ~129.5 MiB PSS in debug and ~85.7 MiB PSS in release. These are observations on one image/device, not peak-memory bounds, matched benchmarks or evidence of real-projector performance.

## Remaining limits

This audit and regression suite do not prove absence of bugs or exercise every menu/provider/Android-version combination. Especially pending: physical low-RAM/32-bit projectors, slow/removable USB, revoked/partial media permissions, minimum-API rendering, 16 KB runtime, sustained stress, accessibility and overscan. Native image decoding and third-party provider calls are not interruptible merely because a coroutine is cancelled. Filter failures recover to the base image but currently lack a dedicated user-facing error for every effect. TalkBack/voice accessibility and comprehensive localization have not been implemented.

See [Play readiness](PLAY-READINESS.md) for signing, permissions review, policy declarations and account/testing gates. Approval by Google has not been requested and is not guaranteed by this candidate.
